## Feasibility assessment до изменений

Verdict: **CONDITIONAL GO**. Основной агент и отдельный read-only architect
независимо оценили исходную реализацию до правок. Простой путь проверки есть,
но evidence для уверенного прогноза прохождения всего #234 за два кандидата нет.

| Направление | Прогноз | Уверенность |
| --- | --- | --- |
| Реализовать поведение без архитектурных изменений | Высокая реализуемость: необходимые поля и точки изменения существуют | Высокая |
| Заметно повысить полезность относительно baseline | Правдоподобно, размер эффекта неизвестен | Средняя по механизму, низкая по размеру эффекта |
| Пройти все критерии максимум за два кандидата | Существенно неопределённо: строгий gate и прежние потери фактов могут остаться | Низкая |

Осмысленные численные вероятности не выводятся из имеющихся данных. Нет
сравнительных ответов кандидата, репрезентативной выборки или измеренной
вариативности. Эти качественные оценки — инженерный прогноз, не статистика.

Действующий prompt разрешает прямое практическое значение и потенциальный риск,
но «может» и «допускается» оставляют пересказ или `null` равноправным выбором.
Непустой `impact` также может лишь сохранять `consequences`. Это сохранение
факта, а не новое обогащение. Baseline schema description описывает только
перенос `consequences`, включая `source="consequences"` и запрет добавлять
последствия при перефразировании. Формального противоречия JSON Schema нет,
но вторая роль поля не описана. Возможное конфликтующее побуждение — гипотеза,
не установленная причина поведения модели.

`problem`, `circumstances`, `impact` достаточны: первые два сохраняют свои
фактические роли, третий вмещает последствия и краткий вывод. Без категории
`subject` ограничен `null`, но `impact` доступен. Категория не нужна для общего
вывода и не доказывает его истинность.

Основные способы провала: выдуманная причина, узел или ремонт даже со словом
«возможно», новый субъект или событие, подмена факта риском или риска событием,
повтор `consequences`, общая добавка без пользы, потеря отрицания, условия или
факта исправности. Риск остаётся во всех генеративных полях, включая warnings.
Schema/parser подтверждают форму, но не достоверность прозы.

При любой категории prompt содержит правила всех шести предметов. Общая правка
может повлиять на дверь, уборку, освещение, лифт, кровлю и вентиляцию.
Нормативный gate проверяет confirmation, совпадение `kind` и происхождение
evidence. Согласованно ошибочный предмет с настоящей цитатой всё ещё способен
включить неподходящий модуль. Вывод не является новым evidence. Правка prose
не устраняет это ограничение gate.

Baseline prompt занимает 20549/35531 UTF-8 bytes без/с confirmation.
`impact` ограничен 500 символами, `problem` — 1526, `circumstances` — 600.
Динамический бюджет равен 1537, body — 2500, максимальный нормативный блок —
959. Индивидуальные максимумы нельзя складывать как доступный объём:
учитываются пункт требований, разделители и structured location. Переполнение
отклоняется без усечения. Добавка должна уступать существенному вводу.
Output cap 4000 сохраняется. Длинная подборка примеров не предлагается.

D содержит восемь случаев, три положительных. Два положительных — освещение,
все три без confirmation. Этого достаточно для раннего опровержения гипотезы
и пяти controls, но недостаточно для прогноза полного PASS. В 39 сценариях
confirmation отсутствует в 23, дверь представлена в 8, уборка — в 3, лифт —
в 4, освещение — в 1, кровля и вентиляция — в 0. Набор не расширяется:
его PASS не докажет semantic качество каждого из шести предметов.

## Кандидат 1 и офлайн-готовность

Гипотеза: предпочитать один новый непосредственный полезный вывод при
достаточном основании в исходных фактах, иначе воздерживаться. Практическое
значение предпочтительнее риска. Явные последствия сохраняются целиком,
повтор и общая фраза не считаются обогащением. При нехватке общего лимита
добавка уступает существенным сведениям.

В production-коде изменены только инструкции `packages/llm/src/request-draft.ts`
и description `impact` в `packages/llm/src/request-draft-json-schema.ts`.
В существующем route-тесте обновлён независимый anchor хеша prompt в diagnostics.
Новых примеров нет.
Description является частью версии кандидата. Структура output, nullable
abstention, parser/core/renderer, fallback #306, `desiredActions`, нормативные
тексты/gate, HTTP/UI, privacy/diagnostics и один вызов сохраняются.
Второй кандидат не реализован, #268 не включён. Старую фразу fallback в
историческом ADR-0004 не следует принимать за действующий контракт #306.

Исполняемое детерминированное поведение не меняется. Для декларативных инструкций
не создан искусственный red/green тест на совпадение новой фразы: он не
воспроизвёл бы смысловую проблему модели. Сначала проверены существующие 32
prompt/schema/corpus tests на baseline, затем 447 focused core/LLM/benchmark
tests на кандидате. Полный запуск обнаружил 24 падения существующей проверки
diagnostics из-за прежнего хеша prompt. Anchor обновлён на новый fingerprint,
без изменения logging-кода. Это проверка отчётности версии, не качества прозы.
Существующие mocks проверяют контракты, не служат новыми LLM-ответами.
Обязательные проверки, CI и exact HEAD фиксируются в Draft PR.

Независимое read-only review TS-diff не обнаружило подтверждённых дефектов.
Кодом подтверждены согласованные инструкции, abstention и отсутствие новых
путей данных. Прогнозируемые риски: «предпочти» может стимулировать пограничную
добавку, удлинение ответа или взаимодействие предметных правил. Неизвестны
до live: прирост полезности, фактическая безопасность, сохранение фактов моделью,
длины и стабильность subject/legal selection. Offline PASS не доказывает
метрики 0 / 5% / 80% и ручную приёмку.

### Review, остановка и допуск

Reviewer, не автор кандидата, получает synthetic input, checked draft,
материализованный draft и весь документ с нормативными абзацами и `Прошу:`.
Где возможно, baseline/candidate скрыты. Для смыслов фиксируются исходный факт
либо новый вывод и его непосредственное основание, hard/semantic verdict,
severity, польза, abstention, reviewer и SHA. Сводка сохраняет raw counts,
denominators и разрезы методики, без новой runtime-онтологии. Владелец отдельно
принимает первые 15 F. Формат записи одного ответа:

```text
SHA / fingerprints / scenario / split / eligibility / repeat / report
attempted / valid / hard verdict / semantic verdict / reviewer
исходные факты / добавленный смысл / основание / сохранение условий
critical / noncritical enrichment error / useful / abstention / пояснение
usage / стоимость или верхний резерв / общий остаток / stop decision
```

Первый подтверждённый critical blocker прекращает прогон. `REVIEW_NEEDED`
приостанавливает вызовы до независимого разрешения. Успешный repeat не исправляет
нарушение. Transport/validation failure остаётся attempt и INCOMPLETE,
не заменяется молча новым ответом. Второй кандидат требует адресной гипотезы
и нового approval, третьего слота нет. Если остатка для обязательного gate нет,
расходы прекращаются. Нельзя настраивать кандидата по F/R.

Офлайн-evidence достаточно для подготовки ограниченного baseline-этапа.
Начало расходов **не разрешено**. Владельцу отдельно подтвердить baseline SHA,
exact HEAD/fingerprints кандидата, закрытый configuration class и допуск,
полноту учёта, восемь одноответных D-порций, максимум 211 ₽, stop rules и резерв
завершения. `RUN 1` не заменяет approval. Кандидат и финальная qualification
требуют следующих отдельных разрешений. Draft остаётся Draft до необходимой
live/semantic qualification. Merge, release и deployment здесь запрещены.
